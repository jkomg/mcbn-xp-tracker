# Project History and Themes

Chronological narrative of mcbn-xp-tracker's major eras/decisions, plus the recurring design principles that should govern future changes. Point-in-time snapshot as of 2026-07-20, built during a full codebase crawl to guard against losing track of why things are built the way they are. Companion docs: [ARCHITECTURE_WEB.md](ARCHITECTURE_WEB.md), [ARCHITECTURE_BOT.md](ARCHITECTURE_BOT.md), [REGRESSION_HYGIENE_CHECKLIST.md](REGRESSION_HYGIENE_CHECKLIST.md).

## Timeline

- **Feb 2026 — Sheets-only era.** Single Flask app reading/writing Google Sheets directly. `RELEASE_2026-02-26_SECURITY_PERF.md`: CSRF, session hardening, constant-time token comparison, batched Sheets writes, and the first Advantage-XP formula bug fix — formula drift as a bug class, which later motivated the shared `xp_costs.json`.
- **Mar 3 — Monorepo migration.** Split into `apps/web` + `apps/bot`, bot deliberately local-hosted to avoid always-on cloud cost. Establishes the web/bot boundary and shared-package concept.
- **Mar 11 — Containerization.** Docker compose profiles + `scripts/bootstrap-local.sh` for turnkey local dev.
- **Mar 13 — Turso DB migration (pivotal turning point).** Sheets demoted from system of record to best-effort backup mirror, written after every DB write, never read for primary data. Why: Sheets doesn't scale to the relational queries/concurrency claims+spends+ledger+audit need. This is where "best-effort side effect never blocks the primary transaction" becomes a codified pattern, not just an idea.
- **Mar 16 — Bot health & fixes.** Three-layer heartbeat monitoring, Docker ARM64 fixes, a `MONOREPO_ROOT` path-resolution fix (Docker restarting containers before bind-mounts were ready broke the shared-package path walk after a host reboot — fixed with an explicit env override rather than relying on directory-walk detection). Establishes the heartbeat+staleness-threshold observability convention reused later for wiki sync.
- **Apr 7 — Broadcast overhaul & scheduler fix.** Autocomplete replaces freetext targeting (typo-proofing); passage-of-time scheduler switched to a `(prevMin, nowMin]` window instead of a fixed check so a bot restart can't cause it to silently skip firing.
- **Apr 14-15 — Chronicle Wiki launch.** New public wiki inside the existing Flask/Turso app (no new infra), staff-edited/player-read, bot-syncable via API.
- **Apr 17-21 — Wiki/Notion sync hardening + 10-phase modularization (the densest, most instructive era).**
  - Shared sync lock so manual and scheduled paths can't race; source-aware acks (manual vs scheduled) so a nightly run can't silently consume a staff-requested manual sync; persisted sync-lifecycle history (`notion_sync_events`) instead of a single current-status key.
  - **A real production outage**: schema drift in Turso (`wiki_pages.sync_locked*` columns missing after a merge) took the wiki down; recovery needed manual schema reconciliation. Directly motivated Cloud Run deploy-default hardening and an automated drift-detection script. **Lesson: migrations must land atomically with the code depending on them; prod needs automated drift checks, not tribal memory.**
  - Per-page sync lock so staff can protect hand-edited pages from automated overwrite.
  - **10 modularization phases**: one monolithic script (`discord-notion-sync.ts`) mixing Discord fetch, Notion API, wiki API, markdown rendering, and taxonomy logic with no tests, decomposed incrementally — each phase extracts one concern, each phase's doc names exactly what the next phase should do. **Lesson: large sync/integration scripts should be decomposed into pure-helper modules + a thin orchestrator with target-separation and orchestration-level tests as the end state — don't leave a monolith "because it works," and don't try to fix it in one giant rewrite either.**
- **Apr 21 — Backgrounds/Ghoul Discipline/wiki ops.** Adding Ghoul Discipline as a spend category required **zero new formula code** — just a JSON entry in the shared package, because `flat_cost` was already a generic mechanism both apps understood. Direct payoff of the shared-packages pattern. Also: `WikiSyncBlock` tombstones so a staff-deleted wiki page can't be silently recreated by the next sync.
- **May 20 — Character approval workflow.** Full `/lasombra approve|edit|update|delete` wizard suite lets staff onboard characters entirely from Discord, calling web API endpoints — never touching DB/Sheets directly. Settings gated behind Administrator role for the first time.
- **May 28 — Character Creator Phase 2.** Full loresheet library, XP budget sidebar, CC Admin tooling — and **Notion fully removed** from wiki sync (wiki sync becomes Discord-only). The elaborate April dual-target machinery was deliberately unwound once Notion proved unnecessary. **Lesson: willingness to delete complexity once it's no longer earning its keep, not just add more.**

The April sync modularization release notes below are historical records of the removed dual-target implementation. Current runtime guidance is in `apps/bot/BOT_MEMORY.md`, `docs/BOT.md`, and `docs/ENV_AND_SECRETS.md`.
- **Jun 4 — GCP security hardening.** Removed `roles/editor`/`roles/owner` from service accounts ("any RCE in the web app had full GCP project access — that path is now closed"), split dev/prod OAuth credentials, and **enforced a manual-approval + dev-first deploy gate for prod** (auto-deploy to dev on CI pass; prod requires manual workflow dispatch + reviewer approval). **This is the direct ancestor of "test on dev guild/environment first."**
- **Jun 18 — Coterie system.** Full lifecycle: proposal, creation-dot allocation, background/XP donation with approve/deny, domain ratings. Explicit doc note: "the server validates the submitting character is an active member of the submitted coterie ID — tampered form fields are silently dropped." Server-side re-validation of client-claimed identity as a recurring theme.
- **Jul 10 — Settings redesign + Scene requests (same day).** Settings became a control panel with per-field "used by" badges — explicit client ask, so staff can see the consequence of a change before making it. Scene requests introduced the **first button-driven claim/reject flow** in the codebase (every prior approve/reject was command-driven), built atomically server-side so only the first click on a `pending` request wins. A broader "Nocturne" dark-theme redesign continued across most staff pages through mid-July, and one such pass surfaced a latent correctness bug (spend queue-order bypass) — a redesign pass finding a real bug, not just cosmetics.
- **Jul 2026 (most recent before this doc)**: DB-backed wish lists (moved off localStorage after a cross-device sync complaint), spend-approval XP-availability guard + reversal capability, `/rumor` @role/#location tag resolution (curated allowlist), wish-list audit logging mirrored to Sheets, and making a disabled cubby-sync worker (then three more workers) loud instead of silent — continuing the "surface silent failures, don't tolerate them" theme.
- **Correspondence command suite** (built incrementally, not a single release): boon ledger + contact-thread persistence → `/deliver` → `/contact send|reply` → `/prestation owe|status|repay` → `/post` and `/cobweb` → `/rumor` ("completes the Correspondence sequence") → embed restyling, Settings-editable channel IDs, `/rumor`'s tag resolution. All commands route through `ctx.adapter.*` into the web API — confirmed none touch a DB or Sheets client directly.

## Recurring principles (the ones that should govern future changes)

1. **Turso is authoritative; Sheets is a best-effort mirror, never read for primary data.** Stated in `RELEASE_2026-03-13_TURSO_DB_MIGRATION.md` and `CLAUDE.md`; enforced in `sheets_sync.py` (every mirror call wrapped in try/except, `logger.warning`, never raised into the request path). Recurs for wiki sync and wish-list mirroring.
2. **The bot never writes to DB/Sheets directly — always via the web API + service token.** Confirmed by spot-checking multiple command files: zero direct DB/Sheets client references outside `ctx.adapter.*`.
3. **Shared packages (`packages/api-contract/spend_categories.json`, `packages/rules/xp_costs.json`) prevent category/rule drift.** Both `apps/web/app/xp_rules.py` and `apps/bot/src/xpRules.ts` load the *same* JSON files (via `shared_contract.py`/`sharedContract.ts`) rather than each authoring their own formula table. Payoff cited directly: adding a new spend category has repeatedly required zero new formula code, just a JSON entry, when the cost mechanism (flat/multiplier/per-dot/level-multiplier) already exists. **One documented fragility**: path resolution across host/Docker boundaries can break after a reboot if the bind-mount isn't ready when the directory-walk runs — `MONOREPO_ROOT` env override is the escape hatch.
4. **Curated allowlist over blanket access, especially for anything with mass-ping/abuse potential.** Explicit in `/rumor`'s tag resolution (the bot posts with its own permissions, so `@` must resolve against a fixed in-fiction role list, never "any guild role"). Same theme in Settings admin-gating, scene-request claim/reject role-gating, and coterie-membership server-side re-validation.
5. **Best-effort side effects never block the primary transaction.** Beyond Sheets sync: wiki sync skips disabled targets rather than failing, background-blank-release DM notifications are best-effort after the DB write already succeeded, Discord deploy-notification webhooks use `continue-on-error: true`, scene-request queue-message recording is explicitly documented as best-effort.
6. **Dev-first / test-on-dev-guild-before-prod.** Formalized in the Jun 4 security-hardening release (auto-deploy dev, manual-gated prod) — origin of the standing rule to validate risky live Discord-server mutations on the dev/test guild first.
7. **Fail loud, not silent, on background/monitoring failures — but this is still a work in progress, not a fully-realized guarantee.** Reapplied multiple times (cubby-sync, then three more workers in the same pass) — treat "a worker logs '...started'" as unverified until you've also confirmed its actual enabled-check fires where you think it does. See [ARCHITECTURE_BOT.md](ARCHITECTURE_BOT.md) for which workers still have the unsafe shape.
